# Build and tooling

The configuration files that build, type-check and lint the frontend.

---

## package.json

**File:** [`frontend/package.json`](../../frontend/package.json)

```json
{
  "name": "lift-tracker-frontend",
  "private": true,
  "type": "module",
  "scripts": {
    "dev": "vite",
    "build": "tsc -b && vite build",
    "lint": "oxlint",
    "preview": "vite preview"
  }
}
```

### Scripts

| Command | Does |
| --- | --- |
| `npm run dev` | Starts Vite's dev server on `localhost:5173` with hot reload and the `/api` proxy. Add `-- --host` to allow other devices (your phone). |
| `npm run build` | `tsc -b` **type-checks** the whole project (fails on any type error), then `vite build` bundles into `dist/` |
| `npm run lint` | Runs **oxlint** with `.oxlintrc.json` |
| `npm run preview` | Serves the built `dist/` on `localhost:4173` (also proxies `/api`). Useful for checking the production build. |

`"type": "module"` makes `.js` config files ES modules. `"private": true` prevents accidental publishing to npm.

### Dependencies

| Package | Kind | Version | Why |
| --- | --- | --- | --- |
| `react`, `react-dom` | runtime | ^19.2 | UI library and its browser renderer |
| `react-router` | runtime | ^8.4 | Routing (declarative mode: `BrowserRouter`, `Routes`, `Route`, `Link`) |
| `@tanstack/react-query` | runtime | ^5.104 | Server-state caching, fetching and mutations |
| `vite` | dev | ^8.3 | Dev server and bundler |
| `@vitejs/plugin-react` | dev | ^6.1 | JSX transform and React Fast Refresh |
| `typescript` | dev | ~6.0 | Type checking (`tsc -b`) |
| `@types/react`, `@types/react-dom`, `@types/node` | dev | | Type definitions |
| `oxlint` | dev | ^1.81 | Fast linter |

Exact installed versions are pinned in `package-lock.json`. Use `npm ci` for a clean install that matches the lockfile exactly (the Docker build does this).

### package-lock.json
**File:** [`frontend/package-lock.json`](../../frontend/package-lock.json). Generated by npm, so don't edit it by hand. Commit it whenever dependencies change.

## vite.config.ts

**File:** [`frontend/vite.config.ts`](../../frontend/vite.config.ts)

```ts
export default defineConfig({
  plugins: [react()],
  server: {
    proxy: { '/api': 'http://localhost:8000' },
  },
})
```

- **`plugins: [react()]`**: JSX support and Fast Refresh (component edits apply without losing state where possible).
- **`server.proxy`**: any request to `/api/...` on the dev server is forwarded to the FastAPI dev server. The browser only ever talks to `localhost:5173`, so there's no CORS. `vite preview` reuses this proxy. In Docker, nginx does the same job.

Vite also handles CSS modules (`*.module.css` → scoped class names) and `public/` (served at the root) without extra config.

## TypeScript config

Three files, using TypeScript **project references**: one for the app code, one for the Vite config (which runs in Node).

### tsconfig.json
**File:** [`frontend/tsconfig.json`](../../frontend/tsconfig.json). No code of its own (`"files": []`); it references `tsconfig.app.json` and `tsconfig.node.json`. `tsc -b` builds both.

### tsconfig.app.json
**File:** [`frontend/tsconfig.app.json`](../../frontend/tsconfig.app.json). Covers `src/`.

| Option | Value | Meaning |
| --- | --- | --- |
| `target` / `lib` | `es2023`, `["ES2023", "DOM"]` | Modern JS plus browser APIs (`Array.prototype.at`, etc.) |
| `module` / `moduleResolution` | `esnext` / `bundler` | Resolve imports the way Vite does |
| `types` | `["vite/client"]` | Types for `import styles from './x.module.css'`, `import.meta.env`, etc. |
| `jsx` | `react-jsx` | The new JSX transform, so no `import React` is needed |
| `noEmit` | `true` | `tsc` only checks; Vite produces the output |
| `allowImportingTsExtensions` | `true` | Allows `import App from './App.tsx'` (used in `main.tsx`) |
| `verbatimModuleSyntax` | `true` | Type-only imports must say `import type { … }` (you'll see this throughout) |
| `allowArbitraryExtensions` | `true` | Allows importing non-TS files like CSS |
| `moduleDetection` | `force` | Every file is a module |
| `skipLibCheck` | `true` | Don't type-check `node_modules` declarations |
| `noUnusedLocals`, `noUnusedParameters` | `true` | Unused variables are build errors |
| `erasableSyntaxOnly` | `true` | Disallows TS-only runtime constructs (enums, namespaces), so the code stays plain JS plus types. That's why `WeightUnit` is a union type, not an `enum`. |
| `noFallthroughCasesInSwitch` | `true` | |

### tsconfig.node.json
**File:** [`frontend/tsconfig.node.json`](../../frontend/tsconfig.node.json). Covers only `vite.config.ts`, with Node types (`"types": ["node"]`) and `module: nodenext`. The other options mirror the app config.

## .oxlintrc.json

**File:** [`frontend/.oxlintrc.json`](../../frontend/.oxlintrc.json)

```json
{
  "plugins": ["react", "typescript", "oxc"],
  "rules": {
    "react/rules-of-hooks": "error",
    "react/only-export-components": ["warn", { "allowConstantExport": true }]
  }
}
```

| Rule | Why it matters |
| --- | --- |
| `react/rules-of-hooks` (**error**) | Hooks must be called unconditionally, in the same order on every render, and only from components or hooks. Breaking this causes subtle bugs. |
| `react/only-export-components` (warn) | Files that export components should *only* export components (constants allowed), so Fast Refresh can hot-swap them. That's why helpers like `lastUnitFor` live in `records.ts`, not in `SetForm.tsx`. Exporting **types** (`SetFormValues`) is fine. |
| Plugin defaults | Include `react(purity)`, which flags impure calls like `new Date()` during render. Clock reads are wrapped in helpers (`todayIsoDate`, `currentWeekday`). |

## Build output

`npm run build` produces `frontend/dist/` (git-ignored):

```
dist/
├── index.html              entry HTML with hashed asset links
├── assets/
│   ├── index-<hash>.js     the whole app (~330 KB, ~105 KB gzipped)
│   └── index-<hash>.css    all CSS (global + modules)
├── manifest.webmanifest    copied from public/
└── icon*.png, icon.svg, apple-touch-icon.png
```

Asset filenames include a **content hash**, so nginx can cache them forever (`immutable`), while `index.html` is served `no-cache` so new builds take effect on the next load.

## Verifying UI without clicking

There are no frontend unit tests. Two lightweight techniques were used during development, needing no extra dependencies:
- **Type-check + lint:** `npm run build && npm run lint`.
- **Headless Chrome screenshots** of the production build at phone widths. See [Testing → Headless screenshots](../08-testing/testing.md#headless-chrome-screenshots).
