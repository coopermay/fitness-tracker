# Backend configuration

The files that define the backend's dependencies, Python version, tooling and environment.

---

## pyproject.toml

**File:** [`backend/pyproject.toml`](../../backend/pyproject.toml)
The project definition read by `uv`.

```toml
[project]
name = "lift-tracker-backend"
version = "0.1.0"
requires-python = ">=3.12"
dependencies = ["alembic>=1.20.0", "fastapi", "psycopg[binary]>=3.3.6", "sqlmodel>=0.0.47", "uvicorn[standard]"]

[dependency-groups]
dev = ["pytest", "httpx"]

[tool.pytest.ini_options]
testpaths = ["tests"]
pythonpath = ["."]
```

### Runtime dependencies

| Package | Why it's here |
| --- | --- |
| `fastapi` | Web framework: routing, validation, OpenAPI docs |
| `uvicorn[standard]` | The ASGI server that runs FastAPI. `[standard]` adds uvloop, httptools and watchfiles (used by `--reload`). |
| `sqlmodel` | Table classes on top of SQLAlchemy 2 and Pydantic 2 |
| `alembic` | Schema migrations |
| `psycopg[binary]` | psycopg 3 Postgres driver with precompiled binaries (no local libpq needed) |

Transitive dependencies (SQLAlchemy, Pydantic, Starlette, Mako, …) are pinned in `uv.lock`.

### Dev dependencies
| Package | Why |
| --- | --- |
| `pytest` | Test runner |
| `httpx` | Required by FastAPI's `TestClient` |

`uv sync` installs dev dependencies by default. The Docker image uses `uv sync --no-dev`.

### pytest settings
- `testpaths = ["tests"]`: `uv run pytest` only looks in `tests/`.
- `pythonpath = ["."]`: puts `backend/` on `sys.path` so tests can `import app`.

> **Not installed:** `fastapi[standard]`, so the `fastapi dev` command isn't available. Use `uv run uvicorn app.main:app --reload`.

### Adding a dependency
```bash
cd backend
uv add some-package            # runtime
uv add --dev some-package      # dev only
```
This updates `pyproject.toml` and `uv.lock` together. Commit both. Rebuild the Docker image afterwards (`docker compose up -d --build backend`).

## uv.lock

**File:** [`backend/uv.lock`](../../backend/uv.lock)
Generated by `uv`. It records the exact version and hashes of every package, direct and transitive. **Don't edit it by hand.** It guarantees that your Mac, the tests and the Docker image (`uv sync --locked`) all use identical versions. `--locked` makes the Docker build fail if the lockfile is out of date with `pyproject.toml`.

Key versions at the time of writing: FastAPI 0.142.2, SQLModel 0.0.47, SQLAlchemy 2.0.54, Pydantic 2.13.5, Alembic 1.20.0, psycopg 3.3.6, uvicorn 0.54.0, pytest 9.1.1.

To upgrade everything within the constraints in `pyproject.toml`: `uv lock --upgrade && uv sync`, then run the tests.

## .python-version

**File:** [`backend/.python-version`](../../backend/.python-version)
Contains `3.12`. `uv sync` reads it and downloads/uses Python 3.12 for `backend/.venv`, even if your system Python is newer (e.g. 3.13). The Docker image uses `python:3.12-slim` to match.

## alembic.ini

**File:** [`backend/alembic.ini`](../../backend/alembic.ini)
Alembic's configuration. The settings that matter:

| Setting | Value | Why |
| --- | --- | --- |
| `script_location` | `%(here)s/migrations` | Migrations folder, relative to this file |
| `prepend_sys_path` | `.` | Lets `env.py` do `import app.models` |
| `path_separator` | `os` | Modern Alembic setting for path lists |
| `sqlalchemy.url` | *(deliberately absent)* | The URL comes from `app.db.DATABASE_URL` via `env.py`, so there's one source of truth |
| loggers | `root=WARNING`, `sqlalchemy=WARNING`, `alembic=INFO` | Shows "Running upgrade …" lines without SQL noise |

The rest is Alembic's generated template (commented-out options for timezones, file templates, post-write hooks). See [Migrations](../03-database/migrations.md).

## Environment variables

| Variable | Read by | Default | Notes |
| --- | --- | --- | --- |
| `DATABASE_URL` | `app/db.py` (and so the app, Alembic and the seed) | `postgresql+psycopg://lifts:lifts@localhost:5432/lifts` | Must use the `postgresql+psycopg://` scheme (psycopg 3) |
| `TEST_DATABASE_URL` | `tests/conftest.py` | `postgresql+psycopg://lifts:lifts@localhost:5432/lifts_test` | The database is created if missing; its tables are rebuilt each run |

There's no `.env` file loading. Variables come from your shell or from `docker-compose.yml`. (`.env` is listed in the root `.gitignore` in case one is added later.)

### A stray `VIRTUAL_ENV` warning
If you see:

```text
warning: `VIRTUAL_ENV=…/fitness-tracker/.venv` does not match the project environment path `.venv` and will be ignored
```

a virtual environment exists at the **repo root** (created by an editor or `python -m venv`) and is activated in your shell. `uv` ignores it and uses `backend/.venv`, which is correct. You can deactivate it or delete the root `.venv`. It's not used by the project and git ignores it (it contains its own `.gitignore`).
